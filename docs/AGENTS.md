# قواعد المشروع والمهارات

## 1. مصدر الحقيقة
- القواعد العامة: `rules` و`bomba-skills`.
- الاستيرادات في واجهة React تمر من `@a` حسب `central-alias-system`.
- تصميم الواجهة يلتزم بـ `design-system` عند بناء واجهات الرعاية الصحية، وبقواعد BomBa العامة في باقي الحالات.
- تعليقات الكود وJSDoc بالعربية المصرية، وأسماء الكود بالإنجليزية.

## 2. المهارات الفعالة
1. `bomba-skills`: المعمارية، الجودة، التوثيق، الاختبارات، الأمان، وGit.
2. `rules`: قواعد التشغيل والتوثيق والـ Monorepo.
3. `central-alias-system`: نقطة الاستيراد المركزية والـ Icon prefix.
4. `git-repo-master`: الترقيم الشجري للفروع والرسائل العربية.
5. `design-system`: يطبق فقط لو المنتج أو الشاشة ضمن Verdana Health.

## 3. قواعد تنفيذ إلزامية
- لا أسرار داخل الكود.
- لا `localStorage` للتوكنات؛ التوكن في الذاكرة والـ refresh داخل HttpOnly cookie.
- أي تغيير قاعدة بيانات يحتاج migration موثقة.
- Backend بنمط controller/service/repository مع Zod والتحقق من المدخلات.
- API responses تستخدم `{ success, data, message }`.
- لا `eval` في المشروع.
- القياسات والألوان في الواجهات تعتمد على design tokens، مع RTL/LTR وAccessibility.

## 4. تعارضات مفتوحة
1. root scripts الحالية تشير لـ Next رغم أن المشروع Vite/Express. القرار المقترح: اعتماد Monorepo scripts.
2. aliases الحالية متعددة (`@app` وغيرها) مقابل فرض `@a`. القرار المقترح: اعتماد `@a` وتحديث الاستيرادات تدريجياً.
3. أمثلة القواعد القديمة تذكر `localStorage` للتوكن. القرار المعتمد حالياً: HttpOnly cookie + memory token.
4. نمط حماية الترخيص باستخدام `eval` يتعارض مع `no-eval`. القرار المعتمد حالياً: منع `eval` وتنفيذ المنطق الحساس على السيرفر عند الحاجة.

لا يتم تغيير النقطتين الأولى والثانية قبل اعتماد المستخدم.

## 5. أسلوب الاستمرارية
في بداية كل جلسة تُقرأ الملفات: `AI_CONTEXT.md` ثم `AI_SESSION.md` ثم `TODO.md`. في نهاية كل جلسة يتم تحديث `AI_SESSION.md` و`CHANGELOG.md`، مع ترقيم شجري للتطورات والقرارات.

## 6. ممنوعات
- لا ملفات أو إعدادات خارج الهيكل المتفق عليه بدون سبب موثق.
- لا commit غامض أو فرع بدون رقم شجري.
- لا تغيير معماري صامت عند وجود تعارض.
